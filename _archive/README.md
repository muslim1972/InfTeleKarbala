# _archive — المخزن الموحّد لكل ما هو مؤقت

لماذا نحتفظ ولا نحذف: ملفات `sql/` هي التاريخ الوحيد المقروء لتعديلات دوال قاعدة البيانات (كثير منها لم يدخل `supabase/migrations`)، وتفيد عند تتبّع سبب سلوك دالة أو استرجاع نسخة سابقة. ملفات `node/` و`data/` توثّق عمليات استيراد البيانات الأولى.

| المجلد | المحتوى |
|---|---|
| `sql/` | استعلامات فحص وإصلاح SQL |
| `shell/` | سكربتات bash للـVPS |
| `powershell/` | ps1 / bat |
| `node/` | js / cjs / mjs (استيراد، فحص، ترقيع) |
| `ts/` | سكربتات TypeScript مؤقتة |
| `python/` | py |
| `docs/` | md قديمة (خطط، تقارير أمنية، سجل تطوير) |
| `data/` | txt / json / xml (مخرجات ونماذج بيانات) |
| `builds/` | حزم بناء قديمة tar.gz/zip (مستثناة من Git لحجمها) |
| `misc/` | غير مصنّف |

داخل كل مجلد: `root/` (كان في جذر المشروع) و`scripts/` (كان في `scripts/`). سجل النقل الكامل: `MOVE_LOG.txt`.

## القاعدة من الآن
- أي ملف مؤقت جديد (فحص، تشخيص، ترقيع) يُكتب مباشرة في `_archive/<النوع>/` أو في مجلد scratch الجلسة — **لا في الجذر ولا في `scripts/`**.
- `scripts/` للأدوات المعتمدة فقط: `deploy-dist.ps1`، `dist-cmp-remote.sh`، `runtime-check.sh`، `AI Scrept/`، `sql/` (دوال الطابوق المعتمدة)، `utils/`.
- لا يُستورد شيء من `_archive` في الكود أو البناء.
